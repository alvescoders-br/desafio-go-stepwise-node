# Rendering Profile: Refactoring Research Spec → Human-Readable Research Document Set

## Input
Agent-native Refactoring Research spec file (RESEARCH-SPEC-*.md).
Single file containing 11 structured sections plus metadata.

## Renderable Sections
(use with `render_scope: section:{name}`)

| Section Name | Source Data | Rendering |
|-------------|------------|-----------|
| index | all sections | Navigation table, quick stats, validation summary, "How to Use", "Next Steps" |
| scope_summary | scope_summary | Migration overview table, goals prose, constraints, exclusions, risk profile table, complexity table, strategy recommendation (derived) |
| codebase_analysis | current_state_analysis | Project structure tree, tech stack table, deprecated APIs, reflection/serialization/internal API tables, module system analysis, integration points |
| compatibility_breaks | compatibility_analysis | Summary counts, breaking changes by category tables, version-by-version break map |
| dependency_migration | dependency_migration_matrix | Summary counts, full dependency matrix table, high-risk narrative (derived), transitive conflicts, migration order |
| build_impact | build_system_impact | Build tool table, plugin table, compiler settings, CI/CD changes, custom scripts, packaging |
| migration_sequence | migration_sequence | Strategy prose (derived), stage overview table, detailed per-stage plans with prerequisites/steps/validation/rollback |
| transformations | code_transformation_catalog | Summary table, per-transformation cards with before/after code blocks, execution order, manual interventions |
| acceptance | acceptance_criteria | Parity table, new capability table, non-functional table, Definition of Done checklist |
| test_strategy | test_strategy | Infrastructure changes, existing test migration, new tests, regression plan, benchmarks, commands |
| audit | RESEARCH-AUDIT file + open_questions | Sources, metrics, validation results, assumptions, gaps, change log |

## Full Render Order

```
1. RESEARCH INDEX (section: index)
   Generate 00-research-index.md
   - Document header: project name, session, date, migration path, mode
   - "Documents" table:
     Render all 11 documents with status and key metric per document.
     Key metrics derived from open_questions.summary:
       01: Risk + Complexity levels
       02: Count of version-sensitive patterns (sum deprecated_apis + reflection + serialization + internal_apis rows)
       03: total_breaking_changes (critical count)
       04: dependencies needing action (needs_bump + needs_replacement + unknown)
       05: build_changes count (sum of all build_system_impact entries)
       06: migration_stages count
       07: total_transformations count
       08: ac_parity + ac_new_capability
       09: tests_to_write + tests_to_update
       10: assumptions count + evidence_gaps count
   - "Quick Navigation" section: numbered guide (start → scope → breaks → deps → sequence → transforms)
   - "Next Steps" section: APPROVE / ITERATE / PAUSE decision block
   - Footer: "Generated by: researching-refactoring v3.0.0"

2. UPGRADE SCOPE SUMMARY (section: scope_summary)
   Generate 01-upgrade-scope-summary.md
   - Document header with YAML frontmatter
   - "Migration Overview" table:
     Render scope_summary.migration_overview fields as key-value rows
   - "Current Application Profile" table:
     Render first 4-5 rows of current_state_analysis.tech_stack
   - "Migration Goals" section:
     Render scope_summary.goals as bulleted list
     IF all items are "[PENDING: goals]" → "Goals not specified in migration spec."
   - "Constraints and Exclusions" section:
     Two sub-sections: Constraints list, Exclusions list
   - "Risk Profile" table:
     Render scope_summary.risk_profile as: Risk Factor | Level | Rationale
     Highlight Critical/High with bold
   - "Complexity Assessment" table:
     Render scope_summary.complexity as: Factor | Rating | Evidence
   - "Recommended Migration Strategy" prose (DERIVED):
     Generate 2-3 sentences from:
       scope_summary.risk_profile.Overall.level + migration_sequence.strategy.approach
     Template: "Based on the {overall_risk} risk profile and {complexity} complexity,
     a {approach} migration strategy is recommended. {rationale from migration_sequence.strategy}."
   - "Complexity Distribution" table:
     Render scope_summary.phase_complexity

3. CODEBASE ANALYSIS (section: codebase_analysis)
   Generate 02-codebase-analysis.md
   - Document header
   - "Project Structure" section: render current_state_analysis.project_structure as tree
   - "Technology Stack (Current)" table: render full tech_stack table
   - "Version-Sensitive Code Patterns" section with sub-sections:
     3.1 Deprecated API Usage: render deprecated_apis table
     3.2 Reflection and Dynamic Access: render reflection_usage table
     3.3 Serialization Patterns: render serialization_usage table
     3.4 Internal/Restricted API Usage: render internal_apis table
     3.5 Version-Specific Language Features: render version_features table
   - "Module and Package Structure" prose (DERIVED):
     Generate from current_state_analysis.module_system fields
   - "Build Configuration Analysis" prose (DERIVED):
     Generate from build_system_impact.tool + .compiler summary
   - "Test Infrastructure" prose (DERIVED):
     Generate from test_strategy.infrastructure summary
   - "External Integration Points" table: render external_integrations

4. COMPATIBILITY BREAKS (section: compatibility_breaks)
   Generate 03-compatibility-breaks.md
   - Document header
   - "Summary" table: derive counts by severity from compatibility_analysis.breaks
   - "Breaking Changes by Category" grouped tables:
     Group breaks by category field (removed_api, behavioral, module_restriction, etc.)
     Each category: table with ID | API/Feature | Version | Replacement | Files | Severity
   - "Version-by-Version Break Map" table: render compatibility_analysis.version_map
     IF refactoring_type == structural → "[N/A — structural refactoring]"

5. DEPENDENCY MIGRATION (section: dependency_migration)
   Generate 04-dependency-migration.md
   - Document header
   - "Summary" table: derive counts by status_flag from dependency_migration_matrix.dependencies
   - "Full Dependency Matrix" table: render all dependencies
   - "High-Risk Dependencies" prose (DERIVED):
     Filter dependencies where risk == High → generate narrative per dependency
     Template: "{group_artifact} requires migration from {current} to {target}.
     This is high-risk because {notes}."
   - "Transitive Dependency Conflicts" table: render transitive_conflicts
   - "Dependency Migration Order" prose (DERIVED):
     Render migration_order steps as numbered sequence with rationale

6. BUILD SYSTEM IMPACT (section: build_impact)
   Generate 05-build-system-impact.md
   - Document header
   - "Build Tool Compatibility" table: render build_system_impact.tool
   - "Plugin Compatibility" table: render .plugins
   - "Compiler Configuration Changes" table: render .compiler
   - "CI/CD Pipeline Changes" table: render .cicd
   - "Build Script / Custom Task Changes" section: render .custom_scripts
   - "Artifact Packaging Changes" section: render .packaging

7. MIGRATION SEQUENCE (section: migration_sequence)
   Generate 06-migration-sequence.md
   - Document header
   - "Migration Strategy" prose (DERIVED):
     Render migration_sequence.strategy as:
     "Approach: {approach}. Rationale: {rationale}."
   - "Stage Overview" table: derive from stages (Stage | From→To | Focus | Breaks | Complexity)
   - "Detailed Stage Plans": one ### per stage with:
     Prerequisites (bulleted), Steps (numbered), Breaking Changes Addressed (BREAK-XXX list),
     Validation Checkpoint (checklist), Rollback Point
   - "Cross-Stage Dependencies" table: render cross_dependencies
   - "Risk Mitigation per Stage" table: derive from per-stage risk fields

8. CODE TRANSFORMATIONS (section: transformations)
   Generate 07-code-transformation-catalog.md
   - Document header
   - "Summary" table (DERIVED): group transformations by category, count files
   - Per-transformation cards:
     ### TRANSFORM-XXX: {Name}
     Addresses: BREAK-XXX | Category: {cat} | Automatable: {yes/partial/no}
     Files: {list}
     Before: code block
     After: code block
     Notes: {notes}
   - "Transformation Execution Order" table: render execution_order
   - "Manual Intervention Required" section: render manual_interventions
     with prose explanation (DERIVED from reason + guidance)

9. ACCEPTANCE CRITERIA (section: acceptance)
   Generate 08-acceptance-criteria.md
   - Document header
   - "Functional Parity Criteria" table: render acceptance_criteria.parity
   - "New Capability Criteria" table: render acceptance_criteria.new_capability
     IF empty → "[No new capabilities in scope]"
   - "Non-Functional Criteria" table: render acceptance_criteria.non_functional
   - "Definition of Done" checklist: render definition_of_done

10. TEST STRATEGY (section: test_strategy)
    Generate 09-test-strategy.md
    - Document header
    - "Test Infrastructure Changes" table: render infrastructure
    - "Existing Test Migration" table: render existing_tests
    - "New Tests Required" table: render new_tests with AC cross-reference
    - "Regression Test Plan":
      4.1 Pre-Migration Baseline prose (DERIVED: "Capture current test results...")
      4.2 Per-Stage Regression table: render regression_plan
      4.3 Final Regression prose (DERIVED: "Full regression on target version...")
    - "Performance Benchmarking" table: render benchmarks
    - "Compatibility Testing" prose (DERIVED: from version-specific test notes)
    - "Test Commands" table: render commands

11. SESSION AUDIT TRAIL (section: audit)
    Generate 10-session-audit-trail.md
    - Document header (session, date, mode)
    - "Sources Consumed" table: from RESEARCH-AUDIT file
    - "Key Metrics" table: from open_questions.summary
    - "Validation Results" table: from validations section
    - "Assumptions Made" table: from open_questions.assumptions_to_validate
    - "Gaps Detected" table: from open_questions.pending_inputs + evidence_gaps
    - "Change Log" section: from RESEARCH-AUDIT (REPAIR mode only)
```

## open_questions Rendering

### Enhancement Suggestions
Transform open_questions into stakeholder-friendly recommendations:

**pending_inputs → Missing Information Notes:**
```
- **{item_id} {field}** (from {section}):
  {Impact statement derived from impact field}.
  **Why this matters:** {Generated explanation of downstream effect}.
```

**evidence_gaps → Verification Required:**
```
- **{item_id}** ({section}):
  {gap description}. Required: {required_evidence}.
  **Risk if unverified:** Breaking change may not exist, or may be missed.
```

### Meeting Agenda
Use `shared/agenda-renderer.md` to generate prioritized agenda from:
- Critical/High evidence_gaps (verification decisions)
- pending_inputs with high impact
- assumptions_to_validate with high impact_if_wrong
- upstream_gaps_carried_forward

## Derivation Table

| Human Field | Agent-Native Source | Derivation Rule |
|-------------|-------------------|-----------------|
| Recommended Migration Strategy (prose) | migration_sequence.strategy + scope_summary.risk_profile.Overall | "Based on {risk} risk and {complexity}, a {approach} strategy is recommended. {rationale}." |
| Module and Package Structure (prose) | current_state_analysis.module_system | Compose from present/absent, module_info_files, package_structure fields |
| Build Configuration Analysis (prose) | build_system_impact.tool + .compiler | Summarize current → required changes |
| Test Infrastructure (prose) | test_strategy.infrastructure | Summarize current → post_migration changes |
| High-Risk Dependencies (prose) | dependency_migration_matrix.dependencies where risk=High | Per-dep narrative: "{artifact} requires migration... high-risk because {notes}." |
| Dependency Migration Order (prose) | dependency_migration_matrix.migration_order | Numbered sequence with rationale from step fields |
| Summary count tables (docs 03, 04) | Computed from section item counts | Count items grouped by severity/status_flag |
| Category narratives (doc 03) | compatibility_analysis.breaks grouped by category | "Category: {N} items affecting {M} files" |
| Manual Intervention prose (doc 07) | code_transformation_catalog.manual_interventions | Per-item explanation from reason + guidance |
| Pre-Migration Baseline (doc 09) | Derived constant | Standard paragraph about capturing baseline |
| Final Regression (doc 09) | Derived constant | Standard paragraph about full regression |
| Quick Navigation (doc 00) | All section names | Standard numbered guide |
| Next Steps (doc 00) | Derived constant + open_questions.summary | APPROVE/ITERATE/PAUSE with condition checks |
| Investigation Summary (doc 02) | Pattern counts from current_state_analysis | "Analysis identified {N} deprecated APIs, {N} reflection patterns..." |

## Partial Rendering Notes

- `full` — render all 11 documents in order (00 through 10)
- `agenda_only` — render ONLY the meeting agenda from open_questions
- `section:{name}` — render ONLY the specified document
- `section:index` — render only 00-research-index.md
- `section:scope_summary` — render only 01-upgrade-scope-summary.md
- `section:compatibility_breaks` — render only 03-compatibility-breaks.md
- `section:transformations` — render only 07-code-transformation-catalog.md
- Multi-section: `section:scope_summary,compatibility_breaks,migration_sequence` renders docs 01, 03, 06
